# Runtime probe failures precede runtime absence

When a Client Surface attaches to an authoritative Runtime Target, evidence that the target exists but rejected or could not satisfy its probe is reported as `runtime_probe_failed` and must not collapse into Runtime Absence. A live PID owns its local Runtime Scope even when its endpoint rejects the request, times out, or refuses the connection, so discovery stops instead of scanning another port; legacy OAuth probing is attempted only when runtime identity returns HTTP 404. Diagnostics expose bounded structured facts, emit non-mutating recovery guidance for agents, and include `Retry-After` only for HTTP 429. This favors correct target identity and actionable failures over opportunistic attachment to another local runtime. Configurable IP exemptions were rejected because reverse-proxy misconfiguration could turn them into a security bypass.
