# 选择 MCP 连接方式

根据配置、路由和运维的责任归属选择方案。服务器数量本身不能决定最佳方式。

## 比较责任与取舍

| 方式         | 适用场景                                   | 责任与取舍                                                 |
| ------------ | ------------------------------------------ | ---------------------------------------------------------- |
| 直接连接 MCP | 客户端已能管理所需后端                     | 通过客户端支持的功能配置各连接并完成认证；无需额外代理进程 |
| 1MCP         | 需要共享清单、过滤、CLI 发现或项目感知后端 | 运行并维护代理及后端，保护访问并验证客户端兼容性           |
| 自定义代理   | 现有实现不能满足所需行为                   | 实现、测试、保护并维护所需协议和路由行为                   |
| 托管代理     | 希望由供应商运维部分基础设施               | 核实具体供应商的功能、数据处理、价格、支持和服务承诺       |

这是架构选择的比较，不是性能测试或供应商调查，不能据此断言成本更低、配置更快、可用性更高或已通过认证。

## 1MCP 提供的能力

- 统一 MCP 端点和 [CLI 工作流](/zh/guide/integrations/cli-mode)。
- 共享[服务器配置](/zh/reference/mcp-servers)、热重载和[过滤](/zh/guide/advanced/server-filtering)。
- [OAuth 与访问控制](/zh/guide/advanced/authentication)。
- [项目感知模板](/zh/guide/project-checkouts)和显式[后端准备](/zh/guide/backend-preparation)。
- [健康端点](/zh/reference/health-check)、日志和按需启用的 [STDIO 恢复](/zh/guide/advanced/performance)。

代理增加一个进程和一次网络或传输跳转。本地 STDIO 后端仍以子进程运行，聚合不会消除其内存或 CPU 需求。1MCP 不提供连接池、分布式集群或可用性服务级别协议（SLA）。请使用实际客户端、协议功能和后端验证兼容性。

## 先用一个后端评估

1. 按[快速上手](/zh/guide/quick-start)配置一个可信后端。
2. 确认目标客户端可以发现并调用其能力。
3. 按实际工作负载检查认证、过滤、故障处理和资源使用。
4. 确认首个后端的连接和调用均可用后，再添加其他后端。

已有桌面配置可参阅[应用整合](/zh/guide/integrations/app-consolidation)。保留回滚路径，在移除旧配置前验证替代连接。
