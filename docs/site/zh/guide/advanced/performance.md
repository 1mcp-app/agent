# 性能与恢复

1MCP 将 MCP 流量转发到已配置的后端。请根据每个后端设置连接和请求超时，并使用日志和健康检查路由调查缓慢或不可用的服务。它不提供负载均衡、熔断器、连接池或正常运行时间保证。

## 有界 Stdio 恢复

自动恢复需要显式启用，且仅适用于 `stdio` 后端服务器。当子进程退出后仍应被监督时，在 `mcp.json` 中设置 `restartOnExit`：

```json
{
  "mcpServers": {
    "local-tool": {
      "type": "stdio",
      "command": "node",
      "args": ["server.js"],
      "restartOnExit": true,
      "maxRestarts": 5,
      "restartDelay": 1000
    }
  }
}
```

`maxRestarts` 是连续自动重启的最大尝试次数：省略时为 `5`，设为 `0` 表示不限制次数，也可以指定正数上限。稳定运行五分钟后，尝试计数会重置。`restartDelay` 是以毫秒为单位的初始延迟；连续失败依次等待该值的 1、2、4、8 倍，之后最大为 16 倍。

HTTP、SSE 和 streamable HTTP 后端条目会忽略这些监督设置。恢复并不承诺失败的后端一定可用，因此调用方仍需处理 MCP 错误，并在关键操作前检查目标服务。

## 后端休眠

后端休眠需要为每个静态 `stdio` 服务器显式启用。它会释放空闲且由运行时独占的进程，同时保留最近一次获取的能力信息供客户端发现。唤醒会创建新的后端会话，因此进程内状态会丢失，首次操作还需等待初始化。只有在接受这些影响时才应启用；1MCP 也无法发现完全隐藏在后端内部的工作。

```json
{
  "mcpServers": {
    "local-tool": {
      "type": "stdio",
      "command": "node",
      "args": ["server.js"],
      "sleep": { "enabled": true, "idleTimeoutMs": 300000 }
    }
  }
}
```

省略 `sleep` 可保持现有行为。配置该对象时必须提供 `enabled`。`idleTimeoutMs` 默认为 `300000`，必须是 `1` 到 `2147483647` 之间的整数；`0` 不能用于禁用计时器。运行时每 `30000` 毫秒检查一次休眠条件，因此实际释放时间可能晚于阈值。此策略按服务器配置，不支持放入 `serverDefaults`。模板服务器继续使用现有实例池清理机制，远程 HTTP/SSE 服务器不支持此策略。

运行时启动时仍会正常初始化后端。空闲计时从初始化和能力刷新完成后开始，或从最后一项被跟踪的操作结束后开始。已连接但不活跃的客户端不会阻止休眠；未完成的请求、订阅、异步任务以及无法确认是否结束的上游操作会阻止休眠。调用方超时或取消并不代表上游工作已经完成。

发现能力和读取状态时使用缓存信息，不会唤醒后端，也不会延长空闲窗口。工具调用、资源读取、提示词获取、订阅和显式刷新会唤醒后端。懒加载与休眠相互独立：

| 懒加载 | 休眠 | 行为                                                              |
| ------ | ---- | ----------------------------------------------------------------- |
| 关闭   | 关闭 | 保持现有直接工具和进程生命周期                                    |
| 开启   | 关闭 | 保持现有元工具和进程生命周期                                      |
| 关闭   | 开启 | 继续公布缓存的直接工具；调用时唤醒后端                            |
| 开启   | 开启 | `tool_list` 和 `tool_schema` 使用缓存信息；`tool_invoke` 唤醒后端 |

缓存能力仍受当前权限、筛选条件以及禁用工具或服务器设置的约束。唤醒后，1MCP 会刷新能力并重新验证操作。并发调用共享一次启动尝试，各自保留独立的取消和截止时间。唤醒失败会返回错误，不会重放操作。失败后进入 `30000` 毫秒冷却期，后续请求可再次尝试；冷却期结束本身不会启动进程。

配置重载会应用策略变更：启用休眠或修改超时时间会开始新的空闲窗口，关闭休眠会唤醒已休眠的后端。禁用、移除服务器和关闭运行时优先于唤醒。主动休眠不会消耗崩溃恢复预算，也不会触发自动重启监督。

只有经过确认、由运行时独占的进程才能被终止。所有权不确定时会阻止休眠，释放失败时会阻止创建替代进程。共享守护进程管理自己的生命周期；释放连接并不代表回收了其全部内存。CLI 或管理控制台状态会显示生命周期状态、最后活动时间、超时时间、阻塞原因以及唤醒或释放失败信息。各平台的进程释放证据以该版本的测试结果为准；配置通过验证本身不代表进程资源已被回收。

## 运维信号

- 使用 `/health/ready` 判断 HTTP 运行时是否可以接收流量；它不表示每个后端都已就绪。
- 使用 `/health/mcp` 查看后端加载和重试进度。
- 在调用已知后端前，使用已认证的 `inspect` API 或 `1mcp inspect` 查看面向客户端的状态。
- 排查事件时设置 `ONE_MCP_LOG_LEVEL=debug`，随后恢复到合适的生产日志级别。

有关启动行为和目录发布，请参阅[快速启动](/zh/guide/advanced/fast-startup)。有关服务器配置契约，请参阅[MCP 服务器参考](/zh/reference/mcp-servers)。
