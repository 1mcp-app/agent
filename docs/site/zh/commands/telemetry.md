# Telemetry 命令

使用 `telemetry` 查看或修改当前操作系统用户的产品使用遥测设置。

```bash
1mcp telemetry status
1mcp telemetry status --json
1mcp telemetry disable
1mcp telemetry enable
1mcp telemetry reset
```

## 作用范围与控制

即使通过 `--context` 或 `--url` 选择了远程运行时，这些命令也只修改本地设置。`--config-dir`、检出目录和项目选择不改变安装状态的存储位置。状态查询和控制命令不计为使用活动，也不会创建 UUID 或队列。帮助和版本查询同样不创建产品状态。

- `status` 显示持久化偏好、当前进程的有效策略、标识是否存在、队列大小和协调状态，不显示 UUID。状态目录不存在时不会创建它。
- `disable` 保存关闭偏好并清除未发送数据，保留已有 UUID。
- `enable` 保存开启偏好，不创建 UUID，也不覆盖进程、CI 或测试抑制。
- `reset` 清除本地 UUID 和未发送数据，保留偏好。只有之后允许采集时才会创建新 UUID；已经发送到服务端的记录不会被删除。持久化的代际记录防止旧进程恢复旧标识或队列。

在文件系统正常运行时，本地运行时会在五秒内观察到已保存的关闭或重置设置，丢弃旧代际事实，并尽力中止自身正在发送的请求。已经传输的数据无法撤回。轮询和发送时机不产生使用活动或标识。重置或重新开启后，之后的真实活动可以申请新代际；接纳尚未完成时到达的活动可能丢失。远程运行时仍遵循其所有者的设置。

## 采集策略

采集默认开启。首次接纳活动前，会在标准错误输出中显示通知，包含关闭命令和文档链接。正常并发启动共享一次通知和一个随机 UUID。在通知已输出但完成状态尚未落盘时崩溃，通知可能重复。

`inspect` 记录固定命令族及成功或失败结果。`serve` 和 `proxy` 在就绪、失败或取消时记录一次启动结果，关闭时不重复记录。后台启动或重启由调用它的父进程负责；受监管的工作进程使用独立的 `runtime_start` 功能计数，包括自动替换。此阶段状态查询和停止不计数。协议 v1 将取消归为失败。不包含参数、服务器或工具名称、路径、业务载荷、凭据、原始错误、诊断、追踪或运行时及会话标识。此阶段未接入其他命令族和 MCP 操作。遥测不会写入 MCP 标准输出。

| 设置                                                                                       | 效果                                                                                                 |
| ------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------- |
| `--product-telemetry=false`、`--no-product-telemetry` 或 `ONE_MCP_PRODUCT_TELEMETRY=false` | 仅抑制当前进程，不修改其他进程的队列                                                                 |
| `DO_NOT_TRACK=true`                                                                        | 抑制当前进程                                                                                         |
| `CI=true`                                                                                  | 默认关闭，需单独指定 `--product-telemetry-ci=true` 或 `ONE_MCP_PRODUCT_TELEMETRY_CI=true` 才允许采集 |
| 已保存的 `disable`                                                                         | 始终优先于进程开启和 CI 开启设置                                                                     |
| 测试进程                                                                                   | 始终抑制，普通端到端测试不能开启采集                                                                 |

布尔值支持不区分大小写的 `true`/`false`、`1`/`0` 和 `yes`/`no`。标准 `CI`/`DO_NOT_TRACK` 未设置或为空时视为 false，其他无效值会被拒绝。两个遥测选项应使用显式值。CI 数据使用独立的 CI 维度。

## 标识、存储与发送

macOS/Linux 的私有状态位于 `~/.config/1mcp/product-telemetry`，Windows 位于 `~/AppData/Roaming/1mcp/product-telemetry`。同一操作系统用户的本地运行时作用域共享此状态。POSIX 目录和文件必须仅所有者可访问（0700/0600）；Windows 使用受保护的当前用户 ACL，并拒绝重解析点。隐私验证不可用或被拒绝时停止采集。状态和控制命令会报告失败，不会误报成功。

摘要包含随机安装 UUID、实际活动发生时间（秒精度）、版本、操作系统、架构、Node 主版本和 CI 分类。计数按 UTC 日期及上述维度聚合。未发送数据七天过期；序列化队列最多 256 KiB，过期或最早数据会被丢弃。每批最多 100 条摘要、64 KiB；每条摘要最多 16 个计数器，每个计数器最多 1,000,000。

发送利用已有执行机会，请求期限为 1.5 秒。每批在唯一一次发送尝试前从持久队列中移除。错误、拒绝、超时、结果不明和进程终止均不会使已尝试的数据重新入队。移除后、传输前崩溃会丢失该批数据。命令、就绪和关闭流程不会等待发送；很短的命令可能丢失最终计数，包括接纳尚未完成的情况。后台定时器和传输句柄不会阻止进程退出。

第一方服务保留明细 90 天，与安装标识关联的活动最多 365 天。不含 UUID 的每日总量可以长期保留。这些计数是安装状态的近似观测，不代表人数或设备数。

## 协调繁忙或不确定

不会因锁的时间过长而抢占仍存活的所有者。确认主锁所有者已退出后，可以在独立的获取守卫下恢复。所有者元数据缺失或损坏、权限不明或守卫遗留时，系统停止采集。`status` 显示 `busy-or-ambiguous`；采集会丢弃工作，不影响原命令。

离线恢复步骤：先停止该操作系统用户的**所有**本地 1MCP 采集进程，检查存在的 `guard/owner.json` 和 `lock/owner.json`，并独立确认每个记录的进程都已退出。只有完成这些检查后，才删除已检查的 `guard` 和 `lock` 目录。保留 `state.json`，包括其中的纪元、代际和偏好。重新启动并查询状态。不能仅凭时间删除协调目录，也不能在其他采集进程可能运行时操作。如果状态本身损坏或隐私检查失败，请保留状态以便诊断并修复具体问题；状态和控制命令会持续报告失败。

长时间运行的进程每五分钟提供一次发送时机；轮询和发送计时器不会阻止进程退出。
