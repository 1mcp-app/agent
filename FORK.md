# Форк 1MCP Agent (Posiflora)

Это наш форк хаба MCP-серверов. Он нужен, чтобы держать свои правки в исходниках и не терять их при обновлениях.

- **Upstream (источник):** https://github.com/1mcp-app/agent (remote `upstream`)
- **Наш форк:** https://github.com/Andrew-153/1mcp-hub (remote `origin`)
- **Рабочая ветка:** `posiflora/hub-0.39` (от тега upstream `v0.39.6`)
- **Где лежит локально:** `C:\Work\MCPs\1mcp-agent`; конфиг и данные хаба отдельно: `C:\Work\MCPs\1mcp-hub`
- **Ветка `main` форка** повторяет upstream `main` (сейчас 0.40.0-beta), рабочим хабом не является.

## Наши правки

| Файл                                                             | Что и зачем                                                                                                                                                                                                                                                                                                                                                                                         |
| ---------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/sdk/legacy/server/protocol/privateInteractionConnection.ts` | Вызовы идут через общий процесс сервера, а параллельные вызовы к одному серверу ставятся в очередь. В upstream 0.39.x клиент нового протокола (Claude Code) получал **отдельный процесс сервера на каждый вызов**: `mcp-atlassian` падал с `interaction_lost`, остальные серверы тратили секунды на холодный старт. Старое поведение: переменная окружения `ONE_MCP_INTERACTION_ISOLATION=private`. |
| `src/core/validation/schemaPolicy.ts`                            | Лимиты проверки схем тулов подняты: компиляция 250 мс → 3000 мс, проверка аргументов 50 мс → 500 мс (переменные `ONE_MCP_SCHEMA_COMPILE_MS`, `ONE_MCP_SCHEMA_EVALUATE_MS`). На загруженной машине таймаут убивал рабочий поток проверки, вызовы падали с `schema_evaluation_timeout`, а у новых сессий пропадали тулы целых серверов (`mcp-atlassian`, `jmeter`, `windows-computer-use`).           |

## Как собрать и обновить хаб

```bash
cd C:/Work/MCPs/1mcp-agent
corepack pnpm install --frozen-lockfile
sh scripts/build.sh          # нужен pnpm в PATH (обёртка над `corepack pnpm`)
```

Затем перезапустить хаб (остановка `1mcp serve --stop --config-dir C:/Work/MCPs/1mcp-hub`, запуск задачей планировщика «1MCP Hub»).
Подробности и порядок действий: `C:\Work\MCPs\1mcp-hub\README.md`.

## Как подтянуть новую версию upstream

```bash
git fetch upstream --tags
git log --oneline posiflora/hub-0.39..upstream/main      # что нового
git log --oneline v0.39.6..<новый-тег>                    # что изменилось между версиями
```

1. Почитать, что изменилось в релизе (особенно `fix(runtime)`, `interaction`, `session`, `stdio`).
2. Создать новую ветку от нового тега (`git checkout -b posiflora/hub-<версия> <тег>`) и перенести наши коммиты (`git cherry-pick`).
3. Собрать, прогнать проверку (вызов Jira из чата и три параллельных вызова), только потом переключать хаб.

Идеально было бы отправить эту правку в upstream как issue/PR: тогда форк не понадобится.
