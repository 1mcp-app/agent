# Code Review Graph

Inspect the installed version's public build/update and status interfaces. Match the readiness probe's expected file set to the actual parser-supported source universe. Some YAML files produce no graph nodes; a generic extension scan can otherwise demand synchronization forever even after a successful native build.

Verify supported additions, edits, and deletions, including untracked files. Do not drop YAML wholesale to silence a mismatch: supported Ansible or Spring content may still need indexing. If the public CLI skips a supported source class, identify the gap; use another documented native interface only after version-specific verification.

Check completed-build markers, checkout identity, source hashes, and coverage together. Node counts or a build SHA alone cannot establish dirty-source freshness. Use the installed CLI's documented output flags rather than assuming `--json` exists.

An earlier 2.3.9 integration stored absolute checkout paths. Do not seed another worktree by copying that database; initialize the target natively unless the installed version provides verified relocation support. Native operation-wide writer ownership and cancellation require their own evidence, even when fixture tests pass.
